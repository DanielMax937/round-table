# 视频生成三模式设计

## 目标

为所有视频任务创建入口增加三种提示词流程选择，同时保持视频任务落库、豆包命令生成、顺序执行和质量审核链路不分叉。

三种模式：

1. `classic`（经典模式）：原样调用 master 当前的 Seedance Skill OS 提示词编译器，作为默认值和旧调用兼容路径。
2. `higgsfield`（纯 Higgsfield）：只依据仓库中已提交的 Hell Grind 制作总结与 CINEDANCE、ACTING、LIRA 原始附件构造提示词。
3. `hybrid`（Higgsfield 增强）：以经典模式的输出契约为骨架，加入 Higgsfield 的镜头契约、引用职责、表演、连续性、物理和 anti-slop 规则。

## 架构

新增统一的视频提示词策略模块。`video-assets.ts` 只负责整理电影、场景、角色、视觉资产和参考图上下文，然后将标准化输入交给策略路由器。路由器按 `promptMode` 调用三套 messages builder。经典模式直接委托给现有 `buildSeedancePromptMessages`，不复制或改写其内容；另两种模式共享标准输入，但拥有独立的 Higgsfield 提示词主体。

Higgsfield 资料加载器只读取仓库内已经提交的资料目录，不依赖被 `.gitignore` 排除的 `third_party/`。加载器为纯 Higgsfield 与混合模式选择不同上下文预算：纯模式获得完整的核心制作说明和按任务选择的附件片段；混合模式获得压缩后的规则摘要，避免淹没经典模式原有意图。资料中的 Hell Grind 人物、剧情、对白和具体镜头只作为方法示例，当前项目事实始终来自任务输入，防止案例内容串入新项目。

纯 Higgsfield 模式遵循 CINEDANCE 的英文交付契约（原始对白不翻译）；经典与增强模式继续遵循当前 Seedance 编译器的中文交付契约。

## 数据流与持久化

两个视频生成界面和自动产制流水线都使用相同的 `VideoPromptMode` 值。POST 请求中的值经过白名单归一化；缺失或非法值回退为 `classic`。所选模式写入 `VideoGenerationJob.promptMode`，用于历史追踪和界面显示。数据库字段默认值为 `classic`，保证已有记录和旧客户端兼容。

任务执行阶段不再重新计算模式：提示词在创建任务时固化，之后 PATCH 执行仍使用任务中已保存的提示词。

## 界面

`WorkflowWizard` 在视频生成区显示三张可选择的模式卡片，并在自动产制流水线复用同一个选择。`BuzzyAgentStudio` 在 Agent Controls 中显示同样的三模式选择。最近任务显示中文模式标签，便于比较同一镜头在不同策略下的结果。

## 错误处理

- 未知模式在 API 边界回退到 `classic`。
- Higgsfield 资料文件缺失时，纯模式和混合模式给出明确的服务器错误，不静默退化为另一模式。
- LLM 返回空提示词时沿用现有失败行为。
- 旧任务没有显式模式时由数据库默认值和客户端兜底显示为经典模式。

## 测试

- 模式归一化：三种合法值、缺失值和非法值。
- 策略路由：三种模式生成不同的 system/user messages，并包含各自必须标记。
- Higgsfield 资料加载：使用已提交资料、阻止目录逃逸、按纯/混合模式控制上下文。
- 请求传播：手动任务和自动产制请求都传递 `promptMode`。
- UI：通过静态契约测试或组件测试确认两个入口存在三种选择并显示任务模式。
- 数据库：Prisma 校验和迁移 SQL 检查。
