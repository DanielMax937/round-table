# AI 视频生成指导

> 本文根据 Higgsfield Studio 公开的《HELL GRIND》Project Brief 整理，将网页中的制作经验重组为一套可执行的 AI 电影生产指南。
>
> 来源：<https://higgsfield.ai/@higgsfield.studio/projects/hell-grind>

## 1. 适用范围

本指南适用于使用图像与视频生成模型制作短片、剧集或长片的团队，重点解决以下问题：

- 人物在不同镜头中变脸、换衣或改变体型
- 场景换角度后空间结构崩坏
- 道具数量、位置和状态无法延续
- 人物声音、口音和表演方式漂移
- 镜头轴线、人物站位和视线关系混乱
- Prompt 反复修改后无法复现成功结果
- 生成素材进入剪辑后节奏、颜色和声音不统一

《HELL GRIND》案例的基本信息：

- 成片约 95 分钟
- 15 人团队
- 预算低于 50 万美元
- 在资产准备完成后，集中生成阶段约 14 天
- 所有画面均由 AI 生成，无实体摄影机、演员和布景

案例中使用的工具包括：

| 环节 | 工具 |
| --- | --- |
| 视频与对白生成 | Seedance 2.0 |
| 人脸与场景生成 | Soul Cinema |
| 图片局部修改 | Nano Banana Pro、Seedream 4.5 |
| 画面文字、道具和反打角度 | GPT Image 2 |
| Prompt 编写与规则执行 | Claude + CINEDANCE/Lira/Acting Skills |

这些工具只是案例实现，本文方法本身可以迁移到其他模型。

## 2. 总体生产流程

```text
故事与剧本
    ↓
场景分块与镜头表
    ↓
角色、场景、道具资产库
    ↓
外观、声音、行为压力测试
    ↓
锁定描述词、命名和参考图
    ↓
建立场景空间地图与镜头轴线
    ↓
按固定骨架编写视频 Prompt
    ↓
按场景批量生成并记录迭代
    ↓
同步剪辑、发现缺失镜头
    ↓
画面清理与统一调色
    ↓
对白清理、声音设计、音乐和交付
```

整个流程围绕一个核心事实展开：

> 视频模型没有跨镜头记忆。人物、场景、道具、位置、声音和行为必须在每个 Prompt 中重新明确。

## 3. 五条总原则

### 3.1 资产优先

在角色、地点和关键道具完成锁定与压力测试之前，不开始正式镜头生成。

### 3.2 每次完整描述

不要假设模型记得上一条 Prompt。已经锁定的资产描述必须逐字复用，不能为了省 Token 随意缩短。

### 3.3 每轮只改变一个变量

一次只修改一行或一个明确问题，其余 Prompt 保持不变，并记录修改内容和结果。

### 3.4 减少模型的自由度

使用明确的空间、数量、动作、时间和参考图角色定义。给模型一个角落比给它整间房更稳定，给它空间地图比让它猜测更稳定。

### 3.5 失败时简化镜头

如果同一个镜头在 10–15 次迭代后仍无法成立，不继续堆砌形容词。应拆分镜头、删除动作或更换角度。

## 4. 项目与资产管理

### 4.1 建立统一资产库

所有角色、地点和道具集中放在一个可浏览的资产库中。案例使用 Canvas 展示：

- 角色设定表
- 场景设定表
- 道具设定表
- 不同状态版本
- 团队备注
- 统一资产标签

建议所有文档、镜头表、Prompt 和生成界面使用同一套标签，例如：

```text
@roco
@roco_wet
@roco_blood
@loc_training_room
@loc_training_room_night
@artifact_full
@artifact_hidden
```

### 4.2 资产的基本定义

一个可用资产由两部分组成：

```text
资产 = 固定文字描述 Descriptor + 参考图片 Reference
```

- Descriptor 负责完整定义人物、地点或道具
- Reference 负责提供视觉锚点
- 两者必须一起进入相关镜头的 Prompt
- 锁定后，Descriptor 应作为常量管理

### 4.3 建议的资产登记字段

```markdown
## 资产 ID

- 标签：@asset_name
- 类型：角色 / 场景 / 道具
- 状态：基础 / 受伤 / 潮湿 / 夜间 / 破损等
- 固定描述：
- 参考图片：
- 使用范围：
- 禁止继承的内容：
- 压力测试结果：
- 锁定版本：
```

## 5. 角色资产制作

### 5.1 人物设定表

案例使用三张核心图片：

1. 面部近景
2. 正面全身
3. 背面全身

正面全身图可以去掉头部，使模型只能从高清面部近景中读取身份，避免宽景镜头从模糊的小脸提取错误面孔。

### 5.2 选择可信的脸，而不是最漂亮的脸

判断标准：

- 皮肤是否有真实纹理
- 面部是否存在自然的不对称
- 眼睛是否有合理的 catch-light
- 不同光线下是否仍像同一个人
- 进入视频后是否能够承载细微表演

人物设定表应有意保持朴素：

- 中性灰背景
- 平直、清楚的光线
- 不磨皮
- 不预先加入过度电影颗粒和镜头效果
- 以大尺寸 3/4 面部角度作为主要身份参考

电影感应主要来自场景资产和视频 Prompt，而不是人物身份证件式资产。

### 5.3 只进行局部修改

服装、伤口、疤痕和血迹应通过局部遮罩修改：

1. 在原始角色设定图上生成需要改变的局部
2. 使用遮罩把改变部分合成回原图
3. 保留未修改区域的原始皮肤与颜色

原则：不要让整张人物图反复经过生成模型。每次完整重绘都会损失纹理、产生色偏，并使脸部逐渐对称、塑料化。

### 5.4 每种状态单独建资产

不要在同一个描述中混合多个状态：

```text
@roco          基础状态
@roco_wet      潮湿状态
@roco_blood    受伤流血状态
```

同样的拆分规则适用于：

- 场景的日间、夜间和雨天状态
- 道具的完整、破损、隐藏和特写状态
- 服装变化
- 人物能力变化

状态拆分的成本低于在每个镜头中纠正模型混合状态的成本。

## 6. 资产压力测试

每个角色资产锁定前至少进行十次测试，覆盖：

- 不同姿势
- 不同焦段和景别
- 不同光线方向
- 不同情绪与表演状态
- 与其他角色同框
- 在真实场景资产中出现

通过标准：

- 十次测试中均能识别为同一个人
- 与其他角色同框时不交换特征
- 宽景和近景保持同一身份
- 不同光线下服装、肤色和面部仍稳定

如果测试失败，优先修改 Descriptor，而不是归咎于随机性或继续盲目抽卡。

## 7. 声音与行为锁定

### 7.1 声音不是图片资产，但必须像资产一样管理

在生成对白前，为每个主要角色锁定：

- 音域与音色
- 说话速度
- 口音
- 句子节奏
- 情绪基调
- 永远不变的表演限制

可复用的声音描述格式：

```text
Voice: [音域与音色]; [速度与节奏]; [口音]; [情绪与表达方式]; [固定限制].
```

网页给出的示例强调了低沉沙哑的男低音、缓慢节奏、伦敦街头口音，以及始终保持平静的威胁感。

使用规则：

- 同一角色每次说话都粘贴完全相同的声音描述
- 对声音进行多次生成压力测试
- 如果发生漂移，收紧文字定义并重新测试
- 不在不同场景中临时重写角色的基础声音

### 7.2 建立角色行为档案

每个主要角色在正式生成前建立一段固定的行为档案：

- 如何走路和转身
- 手在空闲时做什么
- 紧张时的习惯动作
- 眼神如何移动
- 呼吸和身体节奏
- 如何掩饰情绪
- 在压力下如何失控

具体场景可以改变姿势和动作，但角色的行为核心不变。某个习惯在当前姿势下无法执行时，应把能量转移到其他可见动作，而不是直接删除。

## 8. 场景资产与空间连续性

### 8.1 为未来机位生成场景

场景参考图优先使用 3/4 角度，而不是纯正面角度。3/4 视图能给模型提供更多深度信息，支持更大范围的摄影机角度。

每个场景应包含：

- 一个或多个明确的空间锚点，例如柱子、灯、沙发、祭坛
- 单一、可解释的主光源
- 固定的阴影方向
- 可供人物站位参考的距离关系
- 正向角度和需要的反打角度

反打角度可以通过以下方式建立：

1. 使用图像模型生成同一地点的另一角落
2. 生成空场景的缓慢漫游视频
3. 从漫游视频截取需要的机位
4. 对截图进行纹理和灯光修整

### 8.2 明确每张参考图的角色

不要只附图片，必须说明图片用途：

```text
@roco for character reference
@jaxx for character reference
@loc_cave_front for location reference
```

对于地点参考图，应明确限制：

```text
只使用空间结构与纹理；不要把参考图作为第一帧，不继承其构图、机位或整体色调。
```

否则模型可能把人物参考当作构图参考，或把地点图中的颜色和机位错误复制到新镜头。

### 8.3 建立 GEO SPATIAL LAYOUT

每个场景建立一份固定空间地图，在该场景的每个镜头中逐字复用。

```text
GEO SPATIAL LAYOUT

- 地标 A：位置、尺寸、方向
- 地标 B：相对 A 的位置和距离
- 表演区：相对地标的位置
- 摄影机区域：摄影机允许所在的一侧
- 180° 轴线：摄影机禁止跨越的线
- 主光源：方向和人物受光关系
```

空间描述规则：

- 使用 `frame-left` 和 `frame-right`
- 从摄影机视角定义左右
- 使用地标和米数定义距离
- 每次切镜后重新声明人物站位和视线
- 静态对白尽量限制在场景的一小部分，而不是开放整间房

## 9. 视频 Prompt 固定骨架

每条正式 Prompt 使用相同结构：

1. `SCENE CONTEXT`
2. `ACTIVE REFERENCES`
3. `LOCATION MAP`
4. `FIRST FRAME AND SPATIAL BLOCKING`
5. `FORMAT MODE`
6. `OPTICS`
7. `CAMERA`
8. `ACTION TIMING`
9. `PHYSICS`
10. `LIGHTING`
11. `AUDIO`
12. `CHARACTER ACTING`
13. `STYLE`
14. `QUALITY`
15. `POSITIVE CONSTRAINTS`

### 9.1 可复用模板

```markdown
SCENE CONTEXT

EXACT [N] CHARACTERS — NO DUPLICATES: [角色列表]。
[地点、时间、剧情功能、镜头长度和冲突]。

ACTIVE REFERENCES

@[角色] for character reference — [当前状态]。
@[地点] for location reference — only use the space and texture；不继承构图、机位和色调。

LOCATION MAP

[粘贴该场景锁定的 GEO SPATIAL LAYOUT]

FIRST FRAME AND SPATIAL BLOCKING

[第一帧已经有什么、人物站位、面向和相互距离]

FORMAT MODE

[单一连续镜头 / 硬切多镜头]，[时长]，实时，无变速。

OPTICS

[焦段、摄影机高度、主体距离、景深与对焦计划]

CAMERA

[摄影机运动、呼吸感、允许和禁止的运动]

ACTION TIMING

0.0–[x]s — [一个清晰动作节拍]
[x]–[y]s — [下一个动作节拍]

PHYSICS

[重量、惯性、接触、液体、布料、道具的物理反应]

LIGHTING

[唯一主光源、方向、明暗关系、禁止的补光]

AUDIO

[环境音]。
[角色声音固定描述]。
角色只说："[准确台词]"。
其他人不说话。SFX only. No music.

CHARACTER ACTING

[角色状态、目标、阻碍、隐藏内容、身体节奏、行为变化]

STYLE

[粘贴锁定的项目 Style Prefix]

QUALITY

[皮肤、细节、稳定性、无闪烁、无身份漂移]

POSITIVE CONSTRAINTS

[准确人数、物体数量、左右关系、道具状态和摄影机区域]
Photoreal. NON-IP. [画幅]. [时长]s. SFX only. NO CGI. Cinematic.
```

## 10. Prompt 写作规则

### 10.1 现在时、短句、单一节拍

- 使用现在时
- 使用直接、清楚的短句
- 每个动作节拍不超过约三句话
- Prompt 可以很长，但单个时间段不能塞入过多动作
- 摄影机运动应写进动作过程，而不是与动作脱节

### 10.2 优先使用正向动作描述

与其写：

```text
他没有仰面倒下。
```

不如写：

```text
他向前倒下，胸口和手掌先接触地面。
```

重要数量和限制写成画面中实际存在的内容：

```text
画面中准确出现三个人。
房间内只有一个人体模型。
水晶只覆盖角色右臂，从手腕延伸到肩膀。
```

涉及年龄、未成年人或其他敏感内容时，必须遵守所用平台的安全规则，避免含混、冲突或不必要的年龄描述。

### 10.3 固定 Style Prefix

项目应维护唯一的 Style Prefix，并逐字粘贴到每个镜头中。其内容至少覆盖：

- 摄影媒介和真实感
- 镜头与快门运动模糊
- 光源与摄影机受光侧
- 固定色彩比例
- 皮肤细节
- 表演微动作
- 重力、重量和接触阴影
- 构图规则
- 连续性要求
- 帧率与稳定性
- 环境音、无生成音乐、无字幕

音乐应留给后期。生成阶段使用环境音和必要对白，以免模型生成的临时音乐影响剪辑。

## 11. 第一秒与镜头轴线

复杂场景可在每段生成的开头安排约一秒广角镜头，用来固定：

- 人物站位
- 道具位置
- 光源方向
- 场景地标
- 摄影机所在轴线

这段广角不承担复杂动作。它的作用是让模型先建立当前空间布局。

如果新片段承接上一段对白，可以把上一句对白的尾部放入这一秒，让人物反应、口型和情绪更容易跨片段衔接。

## 12. 表演指导

### 12.1 写行为，不只写情绪

不要只写：

```text
他很悲伤。
```

应描述可见的身体变化，例如：

- 下颌绷紧又释放
- 鼻翼轻微移动
- 一次缓慢眨眼后连续眨眼
- 胸口以短促节奏起伏
- 手指停止原本的工作
- 视线先到达目标，头部稍后才转过去

### 12.2 写物理，不只写形容词

表演必须服从身体和道具的物理状态：

- 重物拖低一侧肩膀
- 液体随托盘停止而倾斜、回正
- 衣服和头发延迟跟随身体动作
- 受伤的手存在细微颤抖
- 角色停步后身体仍有惯性

### 12.3 给角色目标、阻碍和变化

每个表演段至少明确：

- 角色想得到什么
- 什么阻碍了他
- 他在隐藏什么
- 主要身体节奏
- 本镜头中发生了什么变化

有效的表演不是持续保持同一种情绪，而是不断改变争取目标的方法。

### 12.4 保持微观生命感

- 每一到两秒出现一个微小可见事件
- 对方台词结束前，听者可以提前产生反应
- 重要事件后保留短暂吸收时间
- 情绪不会在切镜后立即消失，呼吸和手部状态应延续
- 让人物在说话时做具体工作，例如修理、倒水、整理、计数
- 用“保持张力”描述静止，不使用容易冻结画面的空泛静止词

## 13. 对白与声音 Prompt

对白使用固定顺序：

```text
声音和情绪 → 引号中的准确台词 → 身体动作 → 面部反应
```

控制规则：

- 台词只出现在 `AUDIO` 区块
- 明确规定人物只说引号中的内容
- 没有台词的人保持安静
- 面部的轻笑不等于产生笑声
- 写清对白与环境音的混音关系
- 对白出现时，环境音可以适度降低
- 不常见名字应提供明确发音
- 新片段可以从上一段的最后一句开始，以延续口型和情绪

## 14. 镜头表与批量生成

### 14.1 按场景块组织

按影片顺序建立场景块，每个场景块拥有独立镜头表。每个镜头至少记录：

```markdown
- 镜头编号
- 场景编号
- 剧情目的
- 时长
- 景别与焦段
- 角色和资产标签
- 完整 Prompt
- 当前版本
- 生成结果
- 采用/拒绝原因
```

Descriptor、GEO Spatial Layout 和 Style Prefix 应作为常量维护，使一次修改可以同步到相关镜头。

### 14.2 按场景批量生成

生成顺序：

1. 完成一个场景的资产和空间地图
2. 完成该场景所有镜头的 Prompt
3. 按场景批量生成
4. 同步交给剪辑检查
5. 根据剪辑反馈补充反应镜头、手部特写或宽景
6. 场景通过后再进入下一个块

## 15. 迭代与日志

### 15.1 外科手术式修改

每轮只改变一个问题：

- 一句空间描述
- 一个动作时点
- 一个焦段
- 一个参考图角色定义
- 一项数量约束

禁止在一次失败后重写整条 Prompt，否则无法判断哪一部分真正有效。

### 15.2 迭代日志模板

```markdown
## Shot [编号] — Version [版本]

- 生成时间：
- 模型与参数：
- 基础 Prompt 版本：
- 本轮唯一修改：
- 预期解决的问题：
- 结果：通过 / 部分通过 / 失败
- 实际观察：
- 保留内容：
- 下一轮动作：
- 输出文件：
```

### 15.3 10–15 次规则

同一镜头经过 10–15 次受控迭代仍失败时：

- 拆成两个镜头
- 删除次要动作
- 把复杂动作放到片段开头，并从动作已经发生的中间状态开始
- 改变摄影机角度
- 缩小场景范围

## 16. 特殊场景处理

### 16.1 复杂动作

不要把关键复杂动作藏在时间段中部。可以让片段第一帧已经处于动作中，例如角色已经挥动，道具已经开始破裂；接近目标的过程另做一个镜头。

### 16.2 群众

- 把群众作为一个整体资产
- 在群众资产中覆盖不同身高和服装
- 主要群众演员单独建立资产用于特写
- 中景直接明确群众数量，例如 `20+`

### 16.3 跨空间转场

使用门口、拱门或走廊作为空间阈值：

- 同时提供两个地点资产
- 让两个空间在阈值两侧出现
- 使用明显但合理的光色差解释空间变化

### 16.4 巨型角色

每个相关镜头都提供：

- 明确尺寸
- 与人类或车辆的比较
- 画面内可见的比例证据
- 构图无法同时完整容纳其头脚等限制

抽象地写“巨大”不够，必须让画面中存在可测量的尺度锚点。

## 17. 剪辑与后期制作

### 17.1 剪辑与生成并行

剪辑师不必等待所有镜头完成。场景生成后立即进入剪辑，由剪辑反馈：

- 是否缺少手部、道具或反应特写
- 是否需要更宽的建立镜头
- 是否缺少转场或环境镜头
- 对白节奏是否成立
- 哪些镜头需要重新生成

生成镜头的首尾容易出现漂移，应预留剪掉首尾约半秒的空间。

### 17.2 画面清理

画面锁定后单独进行清理：

- 多余手指或肢体
- 沸腾或游移的纹理
- 错误文字
- 面部和手部变形
- 道具突然增加或消失
- 边缘闪烁

小问题逐帧修整。严重问题使用已保存的最终 Prompt，只改变一个针对性条件后重新生成。

清理优先级：

1. 面部近景
2. 手部近景
3. 关键道具
4. 文字与标牌
5. 背景和边缘区域

所有清理应在调色之前完成。

### 17.3 调色

每个生成镜头都可能带有不同的内置色彩。调色首先统一同一场景内相邻镜头，再进行整体风格修整。

场景的核心光色应在前期地点资产中建立，后期调色负责统一和优化，而不是重新发明场景的光线逻辑。

### 17.4 对白与声音

案例优先使用视频模型生成的同步对白：

- 去除噪声
- 统一不同片段中的音色
- 把声音放入正确空间
- 原始对白完全不可用时才补录

声音设计和音乐在后期完成。连续环境音可以把存在轻微画面漂移的生成镜头粘合为同一个空间。

## 19. 最小可行执行方式

这套方法不要求 15 人团队。单人或小团队可以从一个场景开始：

1. 锁定一个角色
2. 锁定一个地点
3. 建立一个 GEO Spatial Layout
4. 写一条固定骨架 Prompt
5. 生成并只修改一个变量
6. 保存每次迭代日志
7. 剪出一个完整场景
8. 完成清理、调色和声音

当这个单场景闭环稳定后，再扩展到更多场景和角色。

## 20. 最终交付标准

一个镜头只有同时满足以下条件才算完成：

- 剧情信息清楚
- 人物身份、状态和行为连续
- 场景地理与轴线正确
- 光线和色彩属于同一场景
- 对白、声音和表演一致
- 动作符合物理重量
- 没有破坏观看的生成缺陷
- Prompt、版本、修改记录和最终文件均可追溯

最终目标不是写出最长或最华丽的 Prompt，而是建立一个能够重复、检查、修正和交付的生产系统。
